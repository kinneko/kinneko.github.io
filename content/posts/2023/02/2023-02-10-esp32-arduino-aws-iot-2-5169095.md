　ESP32にボタンをつけて、ボタンを押したら押された情報がAWS IoTに飛ぶようにしてみる。

　MQTTの接続は通信コスト削減のために、Pubする時だけ接続して、それ以外には接続しないようにしておく。

```cpp
#include <WiFiClient.h>
#include <WiFiClientSecure.h>
#include <PubSubClient.h>

#define BTN_PIN     23
int btnCounter = 0;
const char* ssid       = "MyPlace";
const char* password   = "xxxxxxxxxxxxxxxx";

const char *endpoint = "xxxxxxxxxxxx-ats.iot.ap-northeast-1.amazonaws.com";
const int port = 8883;
char *pubTopic = "v1.0/topic";
const char* rootCA = "-----BEGIN CERTIFICATE-----\n" \
(snip)
"-----END CERTIFICATE-----\n";
const char* certificate = "-----BEGIN CERTIFICATE-----\n" \
(snip)
"-----END CERTIFICATE-----\n";
const char* privateKey = "[REDACTED]";

WiFiClientSecure httpsClient;
PubSubClient mqttClient(httpsClient);
char pubMessage[128];

void setup() {
    pinMode(BTN_PIN, INPUT_PULLUP);

    Serial.begin(115200);
    Serial.println("\nStart...");

    Serial.print("Connecting to ");
    Serial.println(ssid);
    WiFi.begin(ssid, password);
    while (WiFi.status() != WL_CONNECTED) {
        delay(500);
        Serial.print(".");
    }
    Serial.println("\nWiFi Connected.");

    httpsClient.setCACert(rootCA);
    httpsClient.setCertificate(certificate);
    httpsClient.setPrivateKey(privateKey);
    mqttClient.setServer(endpoint, port);
}

void loop() {
  btnCounter = 0;
  while (!digitalRead(BTN_PIN)){
    btnCounter++;
    Serial.print("btnCounter: ");
    Serial.println(btnCounter);
    delay(100);
  }
  if (btnCounter > 0){
    if (btnCounter > 2){
      Serial.println("pushed !");
      Serial.println("Publish.");
      mqttClient.connect("ESP32_device");
      mqttClient.publish(pubTopic, "{\"state\": {\"status\":{\"Button\":\"Pushed !\"}}}");
      delay(1000);
      Serial.println("Published.");
      mqttClient.disconnect();
      delay(1000);
    } else {
      delay(100);
    }
  }
}
```

　thingへの接続に必要な情報はスケッチにハードコードしているけど、そのうちどこかから読み込むようにしなくてはね。量産するときに困るし。

　接続に必要なエンドポイントの情報は、AWS IoT Coreの設定を表示すると表示される。アカウント＆リージョンごとに一意のURLになる。エンドポイントは、「〜.iot.ap-northeast-1.amazonaws.com」になっている。これをコードに記入する。

　からあげさんのブログには、問題点もいくつか指摘されているので、その後どうなっているか調べてみる。

> ESP32でAWS IoTに繋いでThing Shadowを弄る(2) トラブルシューティング編 – コーヒーサーバは香炉である<br>
> <https://blog.maripo.org/2017/07/esp32-aws-iot-troubleshooting/>

　メインループのスタックメモリが少なくて、Loopが回らなくなるような問題があって、loopTaskを4096から8192に増やすといい、という問題。

　動かしてみて、特にエラーにはならかったが、現在はどうなっているか調べる。

　esp32/main.cppの問題のコードの部分は、loopTaskの定義はハードコードではなくなって、「CONFIG_ARDUINO_LOOP_STACK_SIZE」のマクロに変更になっていた。

```text
~/Library/Arduino15/packages/esp32/hardware/esp32/1.0.6/cores/esp32/main.cpp
```

```text
    xTaskCreateUniversal(loopTask, "loopTask", CONFIG_ARDUINO_LOOP_STACK_SIZE, NULL, 1, &loopTaskHandle, CONFIG_ARDUINO_RUNNING_CORE);
```

　CONFIG_ARDUINO_LOOP_STACK_SIZEはどこでどのような値に設定されているかを確認する。3ヶ所で設定されていた。値は8192なので問題なさそう。

```text
~/Library/Arduino15/packages/esp32/hardware/esp32/1.0.6/tools/sdk/sdkconfig
```

```text
　CONFIG_ARDUINO_LOOP_STACK_SIZE=8192
```

```text
~/Library/Arduino15/packages/esp32/hardware/esp32/1.0.6/tools/sdk/include/config/sdkconfig.h
```

```text
　#define CONFIG_ARDUINO_LOOP_STACK_SIZE 8192
```

```text
~/Library/Arduino15/packages/esp32/hardware/esp32/1.0.6/cores/esp32/main.cpp
```

```text
　#define CONFIG_ARDUINO_LOOP_STACK_SIZE 8192
```

　PubSubClientは、MQTTで送信できるパケットサイズがデフォルトで小さく設定されていて、大きいPubがうまく送れないことがある問題。これも128にハードコードされているということだ。MQTT_MAX_PACKET_SIZEを変更する必要があるのだろうけど、現在はどうなっているのだろうか。確認する。

```text
~/Documents/Arduino/libraries/PubSubClient/src/PubSubClient.h
```

```text
#define MQTT_MAX_PACKET_SIZE 256
```

　現在は、倍の256に設定されている。たいしたデータをやり取りすることもないので、ここを増やしてメモリを圧迫しなくてもいいだろう。

　スケッチ内で、「char pubMessage[128];」になっているのは、過去の経緯からだろうか？ 現在は256にしても問題はなさそうだ。
