　カードのほうで遊んでみることはできたので、次はリーダーのほうをマイコンとつなげてみる。

　RFID-RC522モジュールとマイコンの接続はI2Cで行う。MFRC522という名前でも売られている。購入した基板にはV2.0とシルク印刷がされている。

　マイコンに3.3Vを入れると、基板上のパターンで作られたコイルに電気が流される。これがアンテナ兼給電用の磁界を発生する。

　電源のないカードやタグにも同様の回路アンテナが作り込まれていて、リーダーに近づけることで装置内のマイコンの起電力を得るとともに通信を行うようになっている。

　モジュールから出ているピンは、SDA, SCK, MOSI, MISO, IRQ, GND, RST, 3V3とシルクプリントされている。

![](/2023-11-14/6856974-01.png)

　SDAはシリアルデータでI2C用語、I2Cは２線で通信するので、もう一本はシリアルクロック(SCL)なのだけど、SCLは書かれていない。調べてみると、SCLはMISOのピンが使えるようだ。

　SPIはSS/MOSI/MISO/SCKの４線で通信する。SSの表記だけは見当たらない。SSはSDAのピンが使える。

　これ以外にUARTでの通信もできて、SDAがRX、MISOがTXとして使えるようだ。

　リーダーの通信モード設定は、ジャンパとか抵抗値とかで設定されるのが一般的だけど、このモジュールはどうやって設定されているのだろう？

　しょうがないデータシートみるか。

　データシートは、このあたりにある。

<https://www.nxp.com/docs/en/data-sheet/MFRC522.pdf>

　データシートによると、どうやら、電源オンまたはハードリセットの後、自動的にインターフェースをリセットし、セルフで制御ピンの論理レベルを感知後にホストインターフェースタイプを確定して、通信モードを設定するらしい。あったまいー。

　あとは、デバイスドライバがどの通信方式に対応しているか確認がいるかな。

　ターゲットマイコンは、いつも使っているNodeMCU ESP32Sを使う。環境はArduinoが楽かな。Arduinoのドライバを調べる。

　ライブラリマネージャで調べると、なんかいっぱい出てくる... どれがいいのさ？

> pablo-sampaio/easy_mfrc522<br>
> <https://github.com/pablo-sampaio/easy_mfrc522>

![](/2023-11-14/6856974-02.png)

　LGPGL v3。NodeMCU(ESP8266)はサポートされている。1kタグのみでテスト。読み書きは簡単。2022/04/22が最終更新。採用事例はあまりない？ 通信はSPI。

> miguelbalboa/rfid: Arduino RFID Library for MFRC522<br>
> <https://github.com/miguelbalboa/rfid>

![](/2023-11-14/6856974-03.png)

　アンライセンス(パブリックドメイン)。ArduinoとESP8266のサポートはある。2021/11/02が最終更新。わりとデファクトスタンダード。採用事例多し。後方互換性確保のために、積極的な開発は行われていない。UIDを変更するサンプルスケッチあり。通信はSPI。

> MakerSpaceLeiden/rfid: Arduino RFID Library for MFRC522<br>
> <https://github.com/makerspaceleiden/rfid>

![](/2023-11-14/6856974-04.png)

　アンライセンス。miguelbalboaの開発したものをforkし、SPIだけでなくI2CとUARTに対応している。最終更新は２年前。

　ということは、これが大元の元祖なのかな？

> miguelbalboa/rfid: Arduino RFID Library for MFRC522<br>
> <https://github.com/miguelbalboa/rfid>

> kkloesener/MFRC522_I2C<br>
> <https://github.com/kkloesener/MFRC522_I2C>

![](/2023-11-14/6856974-05.png)

　なんでかインストール済み。なんかの依存関係で入ったのかな？ NodeMCUに対応。2021/04/11が最終更新。

> Obsttube/MFRC522_NTAG424DNA: Arduino RFID/NFC Library for NXP NTAG 424 DNA tags using MFRC522.<br>
> <https://github.com/obsttube/mfrc522_ntag424dna>

![](/2023-11-14/6856974-06.png)

　MITライセンス。NTAG 424 DNA カード専用ライブラリ。今回は関係ない。

> nfc-rfid-reader-sdk/MFRC522_PN512: PN512 NFC Reader Library<br>
> <https://github.com/nfc-rfid-reader-sdk/MFRC522_PN512>

![](/2023-11-14/6856974-07.png)

　PN512対応品。本家のfork。今回は関係ない。

> TheNitek/NDEF: NDEF Library for Arduino. Read and Write NDEF Messages to NFC tags with Arduino.<br>
> <https://github.com/TheNitek/NDEF>

![](/2023-11-14/6856974-08.png)

　NFC Data Exchange Format (NDEF)対応ライブラリ。これも関係なさそう。

> OSSLibraries/Arduino_MFRC522v2<br>
> <https://github.com/OSSLibraries/Arduino_MFRC522v2>

![](/2023-11-14/6856974-09.png)

　後方互換性を考慮せずに機能追加を行うもの。SPIとI2Cに対応。ソフトウエアリセットを採用したので、リセットピンの接続は不要。

　中華のカードはUIDを変更できるので、一意の番号としては使用できないと書かれている。うむむ。

　また、このライブラリは、crypto1暗号化通信をサポートしているのだけど、crypto1はクラックされているので、もうセキュリティ技術としては利用できない。まぁ、それはよく知られていることなので問題ない。

　チップはDESFireにも対応しているようだけど、ライブラリは3DESやAES認証は対応できていない。これらは、入手できるカードではないのでそれも仕方がない。

　ざっと見たところでは、Arduino_MFRC522v2か、easy_mfrc522が良さげな感じ。接続インターフェイスは実績的にはSPIがよさそう。接続する線が多いけど。
