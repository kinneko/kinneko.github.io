　とりあえず、アナログ付きのモジュールのほうから試す。

　Arduino UNOのデジタル入力のピンは7を、アナログ入力のピンはA0を使う。5VとGNDも配線する。

　コンデンサマイクからの入力が閾値を超えると、D0にHIGHが出る感じ。A0にはアナログの値が出る。

![](/2023-01-18/5115393-01.png)

　スケッチはこんな感じかな。

　デジタル信号のほうを調べて、HIGHとLOWを出力。そのときに、アナログも読んで値も出す感じ。

```cpp
const int dPin = 7;
const int aPin = A0;
void setup() {
  pinMode(dPin, INPUT);
  Serial.begin(9600);
}
void loop() {
  int dVal;
  float aVal;
  dVal = digitalRead(dPin);
  if(dVal == HIGH){
    Serial.print("HIGH: ");
    Serial.println(aVal);
  }
  else if(dVal == LOW){
    Serial.print("LOW: ");
    Serial.println(aVal);
  }
  aVal = (float)analogRead(aPin) / 1024.0f * 5.0f;
  delay(200);
}
```

　なんか、常にHIGHなんですけど。これってば、なんも調整されてないってことですね。さすが中華品。でも、アナログの値はゼロなんだよな。

　導通試験してみたけど、最低限は導通している感じではある。

　アナログのほうは、ちゃんとハンダが乗っている。

![](/2023-01-18/5115393-10.png)

　出荷時にまったくレベル調整がされていないということはわかったので、アナログ対応のモジュールに5Vを給電してレベル調整をする。LEDが１つ付いているのだけど、現在は両方が点灯している。レベルを調整して、片方が消灯かつ音がしたときに点灯するように調整する。

　が、可変抵抗を回しても、LEDがどちらも消えない... テスタを当てつつ可変抵抗を回すと値は変わっている。やっぱコンパレータが偽物でかつゴミくさい。

　デジタルのみのモジュールのほうは、端子のハンダの盛りが悪いものの、可変抵抗を動かすと、片側のLEDが消えて、マイクからの入力に連動するようになった。しかし、こちらはアナログ出力ピンがないので、詳細なレベル調整ができずに、LEDの輝度に頼るしかない。

![](/2023-01-18/5115393-11.png)

<https://www.youtube.com/watch?v=BEMN_wh7uoA>

　調整後にArdino UNOに繋げてみても、デジタルピンのレベルはずっとHIGHのまま... と、思ったが、可変抵抗を調整していると、たまにLOWになる。なんだこれ？

　結局のところ、入力があるとLOWになるという仕様のようだ。でも、LEDの感度の良さと違って、かなり大きい音がしてもLOWにならないし、200msくらいのサイクルのloopだと反応がすごく鈍い。

　うむむ、このレベルだと使えないなぁ...

　LEDもそうだったけど、徹底して安いの選んだら、こういうめにあうということだねぇ。

　というか、コンパレーターはさむとこうなるので、普通にコンデンサーマイクからの入力をADCで取ったほうがよくない？
