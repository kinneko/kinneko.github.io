　右側にあるインターフェイスから、boot.pyとmain.pyをダウンロードしてみる。

　"Get a file"にboot.pyを入れて、"Get from device"ボタンを押すと、ブラウザのダウンロードモードで普通にboot.pyが落ちてきた。

![](/2023-12-21/7159264-01.png)

　中身はこんな感じだった。さきほど設定したので、webreplが動作するように定義されている。

![](/2023-12-21/7159264-02.png)

~~~text
# This file is executed on every boot (including wake-boot from deepsleep)
#import esp
#esp.osdebug(None)
import webrepl
webrepl.start()
~~~

　boot.pyに追記して、起動時に自動的にAPに接続するようにしてみる。

~~~text
import network
sta_if = network.WLAN(network.STA_IF)
sta_if.connect('MyPlace', 'XXXXXXXXXXX')
sta_if.isconnected()
sta_if.ifconfig()
~~~

　"Send a file"の選択ボタンで、書き換えたboot.pyを指定して、"Send to device"ボタンを押す。

![](/2023-12-21/7159264-03.png)

　再起動ってどうすんだ？ python側からできるのかな？

　まぁ、リセットボタンを押すか。

　これでもリセットできる。

　>>> import machine

　>>> machine.reset()

　boot.py実行時にエラーが出ている。

~~~text

MicroPython v1.21.0 on 2023-10-05; Generic ESP32 module with ESP32
~~~

　状態を確認してみたけど、ダメっぽい。

~~~text
>>> sta_if.ifconfig()
~~~

　シリアルコンソールからネットワークインターフェイスを再設定してもエラーになる。boot.pyで設定しちゃってるからか...

~~~text
>>> import network
>>> sta_if = network.WLAN(network.STA_IF)
~~~

　お作法としては、boot.pyはさわらないほうがいいのかな。

　なんかメンドクサイ...

　ネットワークがアクティブにならないので、WebREPLでboot.pyを修正することができない。これは上書きリセットしかないかな...

　その前に、とりあえず、普通やるLチカをやっておく。ターゲット基板には、2ピンに内臓LEDが接続されている。

~~~text
>>> import machine
>>> import time
>>> led = machine.Pin(2, machine.Pin.OUT)
>>> while True:
...     led.value(1)
...     time.sleep(1)
...     led.value(0)
...     time.sleep(1)
...
~~~

　青いLEDが点滅した。

![](/2023-12-21/7159264-04.png)

　ヘルプを表示してみる。

　>>> help()

　Welcome to MicroPython on the ESP32!

　For online docs please visit http://docs.micropython.org/

　For access to the hardware use the 'machine' module:

~~~text
import machine
pin12 = machine.Pin(12, machine.Pin.OUT)
pin12.value(1)
~~~

　Basic WiFi configuration:

~~~text
import network
sta_if = network.WLAN(network.STA_IF); sta_if.active(True)
sta_if.scan()                             # Scan for available access points
sta_if.connect("<AP_name>", "<password>") # Connect to an AP

~~~


　"Control commands"が気になる。

　「raw REPL mode」ってなんだろ？

　どうやら、コードを直接実行できるようだ。エコーバックはないのかな？

　CTRL-Aを押してみると、raw REPLモードに入った。

　スクリプトをペーストして、CTRL-Dを押すと、ソフトリブートがかかった。boot.pyが壊れているので、実行は失敗してしまった。しょうがないので、CTRL-Bでrawモードを抜ける。rawモードの使い方はわかった。

~~~text
>>>
raw REPL; CTRL-B to exit
>OK
MPY: soft reboot
Started webrepl in normal mode
Traceback (most recent call last):
File "boot.py", line 8, in <module>
OSError: Wifi Invalid Mode
raw REPL; CTRL-B to exit
>
MicroPython v1.21.0 on 2023-10-05; Generic ESP32 module with ESP32
Type "help()" for more information.
~~~

　ペーストモードを試す。CTRL-Eを押す。

　先程のLチカのスクリプトをペーストしてCTRL-Dで戻ってみる。

~~~text
paste mode; Ctrl-C to cancel, Ctrl-D to finish
=== import machine
=== import time
=== led = machine.Pin(2, machine.Pin.OUT)
=== while True:
===     led.value(1)  # LED
===     time.sleep(1) # 1
===     led.value(0)  # LED
===     time.sleep(1) # 1
===
~~~

　Lチカが実行された。

　CTRL-CでREPLに抜ける。

~~~text
Traceback (most recent call last):
File "<stdin>", line 6, in <module>
KeyboardInterrupt:
>>>
~~~

　なんか使いやすくないな... あんまり流行らないわけね...
