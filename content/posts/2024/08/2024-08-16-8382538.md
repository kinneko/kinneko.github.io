　しょうがない地道にX11でやるしかないか...

　Pi3にするデメリットではあるな。64bit環境なのにWaylandにできないのは、メモリが足りないのだろうか。それともGPUドライバの対応の問題だろうか。悲しい。

　タッチスクリーンのデバイス名を調べる。

```
kinneko@pi3:~ $ DISPLAY=:0 xinput -list
⎡ Virtual core pointer                    	id=2	[master pointer  (3)]
⎜   ↳ Virtual core XTEST pointer              	id=4	[slave  pointer  (2)]
⎜   ↳ 10-0038 generic ft5x06 (00)             	id=6	[slave  pointer  (2)]
⎜   ↳ vc4-hdmi                                	id=7	[slave  pointer  (2)]
⎣ Virtual core keyboard                   	id=3	[master keyboard (2)]
    ↳ Virtual core XTEST keyboard             	id=5	[slave  keyboard (3)]
    ↳ vc4-hdmi                                	id=8	[slave  keyboard (3)]
```

　名前は「10-0038 generic ft5x06 (00)」のようだ。とりあえず右回転とタッチの設定を手動でやっててみる。

```
kinneko@pi3:~ $ DISPLAY=:0 xrandr -o right
kinneko@pi3:~ $ DISPLAY=:0 xinput set-prop "10-0038 generic ft5x06 (00)" --type=float "Coordinate Transformation Matrix" 0 1 0 -1 0 1 0 0 1
```

　タッチはうまくいくようになった。

　LXDEのレベルで設定を強制する。

```
kinneko@raspberrypi:~ $ sudo vi /etc/xdg/lxsession/LXDE-pi/autostart
(追記)
@xinput set-prop "10-0038 generic ft5x06 (00)" --type=float "Coordinate Transformation Matrix" 0 1 0 -1 0 1 0 0 1
```

　ダメだわ。反映されない。逆にしてもダメ。もう、しょうがないので起動時にX11で設定するしかないのか。ダサいけど。

```
kinneko@pi3:~ $ sudo vi /etc/X11/xorg.conf.d/99-calibration.conf
Section "InputClass"
    Identifier      "calibration"
    MatchProduct    "10-0038 generic ft5x06 (00)"
    Option          "TransformationMatrix" "0 1 0 -1 0 1 0 0 1"
EndSection
```

　これはうまくいった。

　スリープしないように。デフォルトのスリープ時間は600secになっている。

```
kinneko@pi3:~ $ DISPLAY=:0 xset q | grep "timeout"
  timeout:  600    cycle:  600
```

　DPMS（ディスプレイパワーマネジメントシグナル）は有効になっている。

```
kinneko@pi3:~ $ DISPLAY=:0 xset q | grep "DPMS is"
  DPMS is Enabled
```

xset s off でスクリーンセーバーを無効にする。xset -dpms でDPMS（ディスプレイパワーマネジメントシグナル）を無効にする。

```
kinneko@pi3:~ $ sudo vi /etc/xdg/lxsession/LXDE-pi/autostart
(以下追記)
@xset s off
@xset -dpms
```

　こっちの設定は反映されるのね。

```
kinneko@pi3:~ $ DISPLAY=:0 xset q | grep "timeout"
  timeout:  0    cycle:  600
kinneko@pi3:~ $ DISPLAY=:0 xset q | grep "DPMS is"
  DPMS is Disabled
```

　デスクトップのゴミ箱消す。

```
kinneko@pi3:~ $ grep trash /etc/xdg/pcmanfm/LXDE-pi/*
/etc/xdg/pcmanfm/LXDE-pi/desktop-items-0.conf:show_trash=1
/etc/xdg/pcmanfm/LXDE-pi/desktop-items-1.conf:show_trash=0
/etc/xdg/pcmanfm/LXDE-pi/wizard-items-0.conf:show_trash=0
/etc/xdg/pcmanfm/LXDE-pi/wizard-items-1.conf:show_trash=0
```

　１になっているのは、desktop-items-0.confだけだな。これを0にしてリロードする。

```
kinneko@pi3:~ $ sudo vi /etc/xdg/pcmanfm/LXDE-pi/desktop-items-0.conf
show_trash=0
```

```
kinneko@pi3:~ $ DISPLAY=:0 pcmanfm --reconfigure
```

　ゴミ箱は消えた。

　壁紙を消すか。いろいろ面倒なので、pcmanfmで出しているデスクトップをオフにして消してしまったほうがいいかも。まずは、コマンドラインでテスト。

```
kinneko@pi3:~ $ DISPLAY=:0 pcmanfm --desktop-off
```

　デスクトップが真っ黒になった。メニューバーは消えていない。

　/etc/xdg/lxsession/LXDE-pi/autostartには、以下の設定がある。

```
@lxpanel --profile LXDE-pi
@pcmanfm --desktop --profile LXDE-pi
```

　どうやら、メタ設定としてLXDE-piというプロファイルで管理されているようだ。設定はこのへんか。

```
kinneko@pi3:~ $ sudo find /etc/* | grep LXDE-pi
/etc/xdg/lxsession/LXDE-pi
/etc/xdg/lxsession/LXDE-pi/sshpwd.sh
/etc/xdg/lxsession/LXDE-pi/desktop.conf
/etc/xdg/lxsession/LXDE-pi/autostart
/etc/xdg/pcmanfm/LXDE-pi
/etc/xdg/pcmanfm/LXDE-pi/wizard-items-0.conf
/etc/xdg/pcmanfm/LXDE-pi/desktop-items-1.conf
/etc/xdg/pcmanfm/LXDE-pi/desktop-items-0.conf
/etc/xdg/pcmanfm/LXDE-pi/wizard-items-1.conf
/etc/xdg/pcmanfm/LXDE-pi/pcmanfm.conf
/etc/xdg/lxpanel/LXDE-pi
/etc/xdg/lxpanel/LXDE-pi/wizard
/etc/xdg/lxpanel/LXDE-pi/wizard/panel
/etc/xdg/lxpanel/LXDE-pi/panels
/etc/xdg/lxpanel/LXDE-pi/panels/panel
/etc/xdg/lxpanel/LXDE-pi/config
```

　うーん、細かくみるのがめんどくさい。LXDEそのものを停止するかな。設定をコメントアウトする。

```
kinneko@pi3:~ $ sudo vi /etc/xdg/lxsession/LXDE-pi/autostart
#@lxpanel --profile LXDE-pi
#@pcmanfm --desktop --profile LXDE-pi
```

　再起動すると、真っ黒い画面になった。一応意図通り。

　カーソルだけ残っている。これは消せなかったのじゃなかったかな。なので表示用ファイルを削除して、アイコンキャッシュをリフレッシュする。

```
kinneko@pi3:~ $ sudo mv /usr/share/icons/PiXflat/cursors/left_ptr /usr/share/icons/PiXflat/cursors/left_ptr.bak
kinneko@pi3:~ $ sudo update-icon-caches /usr/share/icons/*
```

　うーん、カーソルは微妙にモタつくな... やっぱPi3ではパワー不足か...

　 --fullscreenにしても、モタつく感じがとれない。

　パラメータにビットレートを絞る方法あったような。

```
kinneko@pi3:~ $ DISPLAY=:0 scrcpy --fullscreen --video-bit-rate 2M
```

　余計モタモタになった...

　スクリーンサイズを指定するmax-sizeを設定してみる。デフォルトでは1080x1920だったのを、576x1024にする。少し機敏になったけど、タッチスタート直後が遅れる。操作感がよくない。

```
kinneko@pi3:~ $ DISPLAY=:0 scrcpy --fullscreen --max-size 1024
```

　今回の実装では、THINKLET側のスピーカー音声が出るので、scrcpyでの音声の中継は必要がない。Pi3側にもスピーカーつけていないし。音声の中継をオフにしてみる。前より、少しマシかな...

```
kinneko@pi3:~ $ DISPLAY=:0 scrcpy --fullscreen --max-size 1024 --no-audio
```

　さらに解像度を432x768まで下げてみる。これで、なかなか機敏になってきた。

```
kinneko@pi3:~ $ DISPLAY=:0 scrcpy --fullscreen --max-size 768 --no-audio
```

　さらに下げて、288x512にしてみる。画面は少し荒い感じでメニューのフォントの幅が微妙に太かったり細かったりすることがあるけど、動きは軽い。まだ少し、マウスのオーバーランがある感じ。

```
kinneko@pi3:~ $ DISPLAY=:0 scrcpy --fullscreen --max-size 512 --no-audio
```

　この状態で、少しメモリには余裕がある。

```
kinneko@pi3:~ $ free -h
               total        used        free      shared  buff/cache   available
Mem:           907Mi       294Mi       122Mi       316Ki       549Mi       612Mi
Swap:          199Mi       1.0Mi       198Mi
```

　さらにタッチの遅延を減らすパラメータの調整。

　バッファサイズを50や20にしてみたけれど、あまり変わらず。ゼロにしてみると、遅延はなくなった。

```
kinneko@pi3:~ $ DISPLAY=:0 scrcpy --fullscreen --max-size 512 --no-audio --display-buffer=0
```

　--max-fps=30でFPSを制限することもできるようだけど、とりあえずバッファで問題なくなった感じ。画面の滑らかさは犠牲になった。

　なんかPi3でもいけそうだな。Pi3Aを買いに行くか。
