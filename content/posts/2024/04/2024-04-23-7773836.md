　引き続き、Yocto Project Quick Buildに沿って、ビルドをやっていく。

> Yocto Project Quick Build — The Yocto Project ® 4.3.999 documentation<br>
> <https://docs.yoctoproject.org/brief-yoctoprojectqs/index.html>

　いまのところ「Yocto Project スタートブック」は使っていない。

　yoctoプロジェクトの運用するgitサーバーから、pokyをcloneする。

> Source Repositories<br>
> <https://git.yoctoproject.org/>

![](/2024-04-23/7773836-01.png)

　pokyは、Yocto Projectのメインコンポーネントで、組み込みLinuxシステムを構築するためのビルドシステムやメタデータの集合体。BitBakeビルドシステム、OpenEmbeddedフレームワーク、レシピ(ソースコードの取得、コンパイル、パッケージング方法などを記述したファイル群)、ターゲット(最小構成,コア,シンプルなデスクトップ,x11,Qtなどの利用方法の違いによるセット)、BSPレイヤー(特定のボードやSoCに対応したハードウェア設定、ドライバ、ツールチェーン)、ツール、ドキュメントが含まれている。

　クイックビルドのページでは、2023/11にリリースされた、v4.3のNanbieldをターゲットにしている。Nanbieldの最新版は2024/4にリリースされた4.3.4。でも、Nanbieldのサポートは2024年5月までと書かれている。

　v5.0 Scarthgapは、この４月にリリースされたもので、LTSが設定されていて2028年4月までサポートされる。でも、ちゃんと動くのかな...

　Nanbieldにするにせよ、Scarthgapにするにせよ、微妙な時期だ。

　まずは、クイックビルドに従ってみることにして、Nanbieldを選ぶ。クイックビルドでは、Nanbieldブランチをmy-nanbieldというローカルブランチ名をつけてにチェックアウトしている。

```text
kinneko@yocto:~/poky$ git checkout -t origin/nanbield -b my-nanbield
Branch 'my-nanbield' set up to track remote branch 'nanbield' from 'origin'.
Switched to a new branch 'my-nanbield'
```

　次にpokyのビルド環境の初期化を実行する。実体はoe-init-build-envスクリプト。つまり、OpenEmbedded開発環境を設定するための初期化スクリプトそのままということ。

```text
kinneko@yocto:~/poky$ cat oe-init-build-env
#!/bin/sh
```

```text
# OE Build Environment Setup Script
#
# Copyright (C) 2006-2011 Linux Foundation
#
# SPDX-License-Identifier: GPL-2.0-or-later
#
```

```text
#
# Normally this is called as '. ./oe-init-build-env <builddir>'
#
# This works in most shells (not dash), but not all of them pass the arguments
# when being sourced.  To workaround the shell limitation use "set <builddir>"
# prior to sourcing this script.
#
if [ -n "$BASH_SOURCE" ]; then
    THIS_SCRIPT=$BASH_SOURCE
elif [ -n "$ZSH_NAME" ]; then
    THIS_SCRIPT=$0
else
    THIS_SCRIPT="$(pwd)/oe-init-build-env"
    if [ ! -e "$THIS_SCRIPT" ]; then
        echo "Error: $THIS_SCRIPT doesn't exist!" >&2
        echo "Please run this script in oe-init-build-env's directory." >&2
        exit 1
    fi
fi
if [ -n "$BBSERVER" ]; then
    unset BBSERVER
fi
```

```text
if [ -z "$ZSH_NAME" ] && [ "$0" = "$THIS_SCRIPT" ]; then
    echo "Error: This script needs to be sourced. Please run as '. $THIS_SCRIPT'" >&2
    exit 1
fi
```

```text
if [ -z "$OEROOT" ]; then
    OEROOT=$(dirname "$THIS_SCRIPT")
    OEROOT=$(readlink -f "$OEROOT")
fi
unset THIS_SCRIPT
```

```text
export OEROOT
. "$OEROOT"/scripts/oe-buildenv-internal &&
    TEMPLATECONF="$TEMPLATECONF" "$OEROOT"/scripts/oe-setup-builddir || {
    unset OEROOT
    return 1
}
unset OEROOT
```

　[ -z "$BUILDDIR" ] || cd "$BUILDDIR"

　このスクリプトは、sourceコマンド経由で動作することを前提にしているようで、中で呼び出された方法をチェックしている。また、環境変数OEROOTが未設定の場合、スクリプトのディレクトリをOEROOTとして設定する。さらに、OEROOT/scriptsにあるoe-buildenv-internalとoe-setup-builddirを読み込む。最後にBUILDDIRが設定されている場合、そのディレクトリに移動して終了している。
