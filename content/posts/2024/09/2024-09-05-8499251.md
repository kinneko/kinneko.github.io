　コードはざっくりとChatGPTに書いてもらう。

　使うライブラリは、camera、path_provider、path、flutter_ffmpegだそうだ。pubspec.yamlに以下を追記するように言われる。

```
dependencies:
  flutter:
    sdk: flutter
  camera: ^0.10.0+2
  path_provider: ^2.0.11
  path: ^1.8.2
  flutter_ffmpeg: ^0.4.0
```

　バージョンの前にキャレットがついているので、指定したバージョンと互換性のある最新のバージョンまで自動的にアップデートされるのだけど、この互換性はあんまりアテにならない。

　Flutterのライブラリのバージョン情報は、セマンティックバージョニング（Semantic Versioning） という方法で管理されていて、ドットで３つの数字をつなげた形で、先頭からMAJOR.MINOR.PATCH の形式で表されている。

　    MAJOR: 後方互換性を破る変更が加えられたときに増加

　    MINOR: 後方互換性を維持しつつ、新機能が追加されたときに増加

　    PATCH: バグ修正など、後方互換性を維持した小さな変更が加えられたときに増加

　バージョンの前にキャレットをつけることで、MINORとPATCHについては、より新しいものがあればそれが適用されることになる。

　念の為、最新版を調べておく。いずれもDart3に対応しているのを確認する。全部最新版になりそうな感じ。

　cameraは、cameraの操作をするライブラリ。OSの違いなどをうまくラップしてくれているので楽な反面、設定がいろいろあってチューニングが必要だと面倒。

　依存関係で、ぞろぞろとライブラリがインストールされた。pubspec.lockのほうに、ダウンロードしたらライブラリのリストが書かれている。

　ダウンロードしたライブラリとpubspec.yamlの内容が異なっているので、これを一致させたい。ビルドに使ったバージョンでない古いものが指定されているのは良くない。けれど、自動でやる方法は提供されていないようだ。手動でやるか放置だな。このくらいやってくれるツールあるといいのに。

```
% vi pubspec.yaml
  camera: ^0.11.0+2
  path_provider: ^2.1.4
  path: ^1.9.0
  flutter_ffmpeg: ^0.4.2
```

　Androidのパーミッション関係の設定をする。AndroidManifest.xmlにカメラの使用とストレージ読み書きの権限を追加する。ChatGPTに指示されたのは以下になる。

```
% vi android/app/src/main/AndroidManifest.xml
<uses-permission android:name="android.permission.CAMERA"/>
<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE"/>
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE"/>

<application
    android:requestLegacyExternalStorage="true"
    ...>
```

　THINKLETはAndroid 8.1なので、パーミッションはこの記述で問題はないのだけど、最近のAndroidはパーミッションが細かく分かれていて、さらにユーザーに許可を求めるインターフェイスや、なぜ許可を求めるのかユーザーに説明していないとストア公開ができなくなっている。世知辛いことだ。

　Android 13(APIレベル33）以上では、新しいグラニュラーパーミッションが採用されている。それに合わせたパーミッション記述をする必要があるし、コードのほうでも個別にユーザーに許可を求めたりという面倒なことをしないと機能が使えない。そのへんは省略するとして、パーミッションだけは正しく書いておく。

　カメラのパーミッションは変更はない。

```
    <!-- Camera permission remains the same -->
    <uses-permission android:name="android.permission.CAMERA" />
```

　READのほうは、Android13からは特定のメディアタイプごとに個別のパーミッションが設定されている。ここでは、イメージとビデオとオーディオを設定する。

```
    <!-- New granular media permissions for Android 13 and above -->
    <uses-permission android:name="android.permission.READ_MEDIA_IMAGES" />
    <uses-permission android:name="android.permission.READ_MEDIA_VIDEO" />
    <uses-permission android:name="android.permission.READ_MEDIA_AUDIO" />
```

　SDK 32以前でビルドする場合のパーミッションも併記しておく。

```
    <!-- Optional: Backward compatibility for older versions -->
    <uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE"
        android:maxSdkVersion="32" />
```

　WRITE_EXTERNAL_STORAGEは、Android 10以降では「Scoped Storage」が導入されたため、非推奨になっている。Android 10以降をターゲットにビルドする場合は、パーミッション設定を変更する必要がある。古い環境向けのアプリをビルドする場合に対応するためにパーミッションを追加する。

```
<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE"
                 android:maxSdkVersion="28" />
```

　一方で、Android 13以降は、アプリケーションが書き込みできるファイル領域は、アプリケーション固有の領域(App-Specific Storage)と共有領域(Shared Storage)に制限されている。全領域に書き込みを可能にするパーミッションも指定できるが、そのようなアプリはストア公開できないので通常は使うことはないだろう。

　書き込み可能な２つの領域のうち、アプリケーション固有の領域への書き込みは特にパーミッションが不要だ。撮影したデータを他のアプリケーションで閲覧したりするときのために、共有領域への保存が必要な場合は、MediaStore APIを使用する。条件によってはグラニュラーパーミッションが必要になることもあるようだ。他のアプリが作ったファイルを操作するようなことがなければ問題ないだろう。

　というわけで、パーミッション関連は以下のようになる。これらのパーミッションを新し目のAndroid端末で利用する場合は、アプリケーションの中で許可を求める操作が必要になるので、そのためのコードも追記する必要がある。
