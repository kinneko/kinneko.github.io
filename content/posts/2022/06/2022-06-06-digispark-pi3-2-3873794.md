　再起動して、Digisparkを差し込んでも、/dev/ttyACM0が生えてこない。

　ボードの設定を行なって、サンプルのDigiBlinkスケッチのコンパイルが通るかどうか確認する。すげー、時間がかかっている...

![](/2022-06-06/3873794-02.png)

　一応通るようだ。

![](/2022-06-06/3873794-03.png)

　書き込みテストをしてみると、エラーになって終わった。エラーメッセージによると、どうやら、デバイスファイルに書き込み権限が足りないようだ。パーミッション問題だ。

![](/2022-06-06/3873794-04.png)

　それっぽいttyAMA0には、ユーザーは書けないパーミッションになっている。

```text
pi@pi:~ $ ls -l /dev/ttyAMA0
crw-rw---- 1 root dialout 204, 64 May 27 18:27 /dev/ttyAMA0
```

　読み書きの権限を追加する。なんか書き込み権限が付かないな...

```text
pi@pi:~ $ sudo chmod +rw /dev/ttyAMA0
pi@pi:~ $ ls -l /dev/ttyAMA0
crw-rw-r-- 1 root dialout 204, 64 May 27 18:27 /dev/ttyAMA0
pi@pi:~ $ sudo chmod +w /dev/ttyAMA0
pi@pi:~ $ ls -l /dev/ttyAMA0
crw-rw-r-- 1 root dialout 204, 64 May 27 18:27 /dev/ttyAMA0
```

　しょうがないので、直接指定する。

```text
pi@pi:~ $ sudo chmod 666 /dev/ttyAMA0
pi@pi:~ $ ls -l /dev/ttyAMA0
crw-rw-rw- 1 root dialout 204, 64 May 27 18:27 /dev/ttyAMA0
```

　再度実行するも、結果同じ。パーミッションエラーになっている。

　ttyAMAじゃなかったのかな？

　デバイスがhotplugされていない感じ？

　デバイスドライバの割り当てがないのかも。

　状態を確認する。認識はしているけど、デバイスの割り当てが起きていない。

```text
pi@pi:~ $ dmesg
[ 2971.850180] usb 1-1.5: new low-speed USB device number 33 using dwc_otg
[ 2971.998922] usb 1-1.5: New USB device found, idVendor=16d0, idProduct=0753, bcdDevice= 1.06
[ 2971.998952] usb 1-1.5: New USB device strings: Mfr=0, Product=0, SerialNumber=0
```

　普通USBシリアルだとttyACM0とかだよな...

　素では動かないようなので、真面目にやるか。

　パーミッションの変更がめんどくさいので、まずは、piユーザーをdailoutグループに入れておく。これはモデムを扱える権限で、つまりシリアルに権限を持つグループに入れるということ。

　調べてみると、最初から入っているし...

```text
pi@pi:~ $ cat /etc/group | grep dialout
dialout:x:20:pi
```

　あとは、Digisparkボードをシリアルドライバと結びつけておく。設定ファイルには"99-com.rules"というシリアル系の設定が作られているのだけれど、それは使わずに別に"00-micronucleus.rules"用意する。

```text
pi@pi:~ $ ls /etc/udev/rules.d/
99-com.rules
```

　設定内容は、先ほどdmesgで取得したDigisparkの情報に合わせる。

```text
pi@pi:~ $ sudo vi /etc/udev/rules.d/00-micronucleus.rules
SUBSYSTEMS=="usb", ATTRS{idVendor}=="16d0", ATTRS{idProduct}=="0753", MODE:="0666"
KERNEL=="ttyACM*", ATTRS{idVendor}=="16d0", ATTRS{idProduct}=="0753", MODE:="0666", ENV{ID_MM_DEVICE_IGNORE}="1"
```

　udevにルールを再ロードさせる。

```text
pi@pi:~ $ sudo udevadm control --reload-rules
```

　こんなもんかな。

　USBポートにDigisparkを差し込んでも、/dev/ttyACM0が生えてこないので、再起動する。

```text
pi@pi:~ $ sudo reboot
```

　こんなことしなくていいmacOSは楽だよなぁ...

　再起動後に、書き込みのテストをしてみる。その前に、普通にDigisparkを差し込んでみたのだけど、シリアルが生えてくる感じはしなかった。

　書き込み待ちの表示になったので、Digisparkを挿入する。

　おっ、なんか書いているね。

![](/2022-06-06/3873794-05.png)

　無事に成功したようだ。

　システムの起動が遅いのと、Arduino IDEの起動が遅いのをガマンすれば、普通に使える気はする。

　このために、専用のPCをUbuntuでセットアップして温存することを思えば、起動用のUSBメモリだけ保管しておけばRaspi3の本体はその時あるものを使えばいいというのはいいかもしれない。
