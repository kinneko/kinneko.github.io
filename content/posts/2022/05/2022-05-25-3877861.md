　ちょっと、画面キャプチャを撮るのにUSB-UVCに接続してみようと思って、前に設定したPi4の例を再履修してみる。

> Raspi4でUSB-HDMIコンバータを使う場合の解像度が細かすぎる<br>
> <https://kinneko.fanbox.cc/posts/1989478>

　Pi3では設定ファイルやシーケンスが複雑ではなく、config.txtのみという感じ。Pi4は大きくお作法が変わってめんどくさいですね。昔のやり方を思い出す。

　デフォルトのconfig.txtの中身。

```text
---
# For more options and information see
# http://rpf.io/configtxt
# Some settings may impact device functionality. See link above for details

# uncomment if you get no picture on HDMI for a default "safe" mode
#hdmi_safe=1

# uncomment the following to adjust overscan. Use positive numbers if console
# goes off screen, and negative if there is too much border
#overscan_left=16
#overscan_right=16
#overscan_top=16
#overscan_bottom=16

# uncomment to force a console size. By default it will be display's size minus
# overscan.
#framebuffer_width=1280
#framebuffer_height=720

# uncomment if hdmi display is not detected and composite is being output
#hdmi_force_hotplug=1

# uncomment to force a specific HDMI mode (this will force VGA)
#hdmi_group=1
#hdmi_mode=1

# uncomment to force a HDMI mode rather than DVI. This can make audio work in
# DMT (computer monitor) modes
#hdmi_drive=2

# uncomment to increase signal to HDMI, if you have interference, blanking, or
# no display
#config_hdmi_boost=4

# uncomment for composite PAL
#sdtv_mode=2

#uncomment to overclock the arm. 700 MHz is the default.
#arm_freq=800

# Uncomment some or all of these to enable the optional hardware interfaces
#dtparam=i2c_arm=on
#dtparam=i2s=on
#dtparam=spi=on

# Uncomment this to enable infrared communication.
#dtoverlay=gpio-ir,gpio_pin=17
#dtoverlay=gpio-ir-tx,gpio_pin=18

# Additional overlays and parameters are documented /boot/overlays/README

# Enable audio (loads snd_bcm2835)
dtparam=audio=on

# Automatically load overlays for detected cameras
camera_auto_detect=1

# Automatically load overlays for detected DSI displays
display_auto_detect=1

# Enable DRM VC4 V3D driver
dtoverlay=vc4-kms-v3d
max_framebuffers=2

# Disable compensation for displays with overscan
disable_overscan=1

[cm4]
# Enable host mode on the 2711 built-in XHCI USB controller.
# This line should be removed if the legacy DWC2 controller is required
# (e.g. for USB device mode) or if USB support is not required.
otg_mode=1

[all]

[pi4]
# Run as fast as firmware / board allows
arm_boost=1

[all]
---
```

　解像度の設定方法は、このあたりに書かれている。

> Raspberry Pi Documentation - The config.txt file<br>
> <https://www.raspberrypi.com/documentation/computers/config_txt.html#custom-mode>

　カスタム表示を設定する場合は、hdmi_cvtというパラメータを使うのがよさそう。設定する細かいパラメータは上記に書かれているのもを入れる感じ。

```text
hdmi_cvt=<width> <height> <framerate> <aspect> <margins> <interlace> <rb>
```

　今回は、上記のページに書かれたサンプルをまるっとコピーして使うことにする。config.txtに以下を書き込んで保存して起動してみる。

```text
hdmi_cvt=800 480 60 6
hdmi_group=2
hdmi_mode=87
hdmi_drive=2
```

　起動してみる。

　ん？指定の解像度になってないじゃん...

![](/2022-05-25/3877861-01.png)

　シャットダウンして、X Windowが落ちると指定の解像度になる。ビデオドライバがリセットしている風だ。

![](/2022-05-25/3877861-02.png)

　framebuffer_widthとframebuffer_heightを設定して強制してやらないとダメ？

　config.txtに追記する。

```text
framebuffer_width=800
framebuffer_height=480
```

　結果同じ。

　ディスプレイのEDIDデータを無視するように設定を追加。

```text
hdmi_ignore_edid=0xa5000080
```

　結果同じ。

![](/2022-05-25/3877861-03.png)

　hdmi_mode設定を変更してみる。

```text
hdmi_mode=85   #720p       60 Hz
```

　やっぱり、X Windowが起動する時点でリセットされてしまう。

　というわけで、正解は、Xの設定ツールで解像度を変更するだった。

![](/2022-05-25/3877861-04.png)

　Preferences -> Screen Configurationでアプリを起動。

![](/2022-05-25/3877861-05.png)

　起動したアプリで、HDMIディスプレイを右クリック。Resolutionから指定の設定を選ぶ。

![](/2022-05-25/3877861-06.png)

　ツールの緑のチェックをクリックすると、表示解像度が変更されて、10秒間の確認モードに入る。OKボタンを押せば確定する。10秒経過したりキャンセルボタンを押すともとの解像度に戻る。

　ハードウエアの制限設定をビデオドライバがオーバーライドしてしまうなって、便利なのか不便なのかよくわからない世の中になりました。RaspiOS手強いわ。
