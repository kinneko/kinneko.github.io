　なんか調べてみると、Pi3はkernelがアップデートされると紐付けで更新されるらしい。なんだそれ...

　それ以外にも、"rpi-update"コマンドで強制アップデートすることもできるらしい。

　ユーザーで実行したら怒られた。

```text
pi@pi:~ $ rpi-update
!!! This tool must be run as root
```

　root権限で実行する。自動で実行されるので、このコマンドを使うのは推奨しないと出る。

```text
pi@pi:~ $ sudo rpi-update

*** Relaunching after update

　調べてみると、実行にはgit-coreパッケージが必要で、それがインストールされていないようだ。rpi-updateパッケージの依存関係がちゃんと記述されていないのね。

```

　推奨されていない強制アップデートをやるのはやめにする。

　すでにインストールされているブートローダーのバージョンを確認する。わりと最近のものなので、更新の必要はなさそうだ。自動更新されていた模様。

```text
pi@pi:~ $ vcgencmd version
Mar 24 2022 13:20:54
Copyright (c) 2012 Broadcom
version e5a963efa66a1974127860b42e913d2374139ff5 (clean) (release) (start)
```

　さて、アップデートされているということは、USBブートができるということだ。

　USBで起動できるメディアは、Pi ImagerでSDを焼くときと同じで、USBメモリに焼くだけ。焼けたUSBメモリをRaspi3に差し込んで起動する。

![](/2022-05-30/3887928-02.png)

　今回はRaspiOSは64bitイメージを選択してみる。

　SDと比べて、書き込みはかなり速い感じがする。

![](/2022-05-30/3887928-03.png)

　ベリファイも速い。

![](/2022-05-30/3887928-04.png)

![](/2022-05-30/3887928-05.png)

　Pi3に差し込んで起動してみる。反応なし... ダメですね...

　なんかSoCのFlashROMに書かれた起動パラメータを変更しておかないと、USBから起動できないような話があった。SDカードから起動しなおして、現在の設定を確認してみる。

```text
pi@pi:~ $ vcgencmd otp_dump | grep 17:
17:1020000a
```

　これが「17:3020000a」でないと起動できないそうだ。直接レジスタ変更するツールは用意されていないようだ。

　このレジスタを変更するには、"/boot/config.txt"に"program_usb_boot_mode=1"を書いて、起動してやる必要があるそうだ。SDカードを編集して書き換え、再起動する。

```text
pi@pi:~ $ sudo vi /boot/config.txt
pi@pi:~ $ sudo reboot
```

　再起動後は、3020000aに書き変わっている。

```text
pi@pi:~ $ vcgencmd otp_dump | grep 17:
17:3020000a
```

　ひょっとして、そのまま再起動すると起動してこなかったりする？ 一応試す。

```text
pi@pi:~ $ sudo reboot
```

　そんなことはないようだ。SDカードから起動してくる。パラメータは優先順位を制御しているだけのようだ。これで、安心して作業ができる。

　USBメモリを差し込んで電源を入れると、起動してきた。パーティションの拡張をやる画面が表示された。その後は、なんだか再起動ループを繰り返している感じだ。

　USBメモリがポンコツだったかな...

　USBメモリのほうにも、"program_usb_boot_mode=1"を書いておかないと、設定がリセットされちゃうのかな...

![](/2022-05-30/3887928-06.png)

　なんか出た。やっぱUSBメモリがポンコツだった可能性があるな。sshの鍵を生成するときに、書き込みに失敗している風だ。

![](/2022-05-30/3887928-07.png)

　違うUSBメモリでやり直してみよう... この小さいメモリ、このために数年前に買ったものだったのだけどなぁ。無念。
