　電源にUNO互換機を使ってしまったので、このままUNOでライブラリの動作確認をやる。

　Arduino IDEに、純正のDFRobotDFPlayerMiniライブラリを入れる。Arduino IDEは1.8.3を使用。

![](/2022-12-22/4945208-01.png)

![](/2022-12-22/4945208-02.png)

　純正のライブラリの開発は、このへんで行われている模様。ほとんど更新はない。

> GitHub - DFRobot/DFRobotDFPlayerMini: Arduino library for DFPlayer<br>
> <https://github.com/DFRobot/DFRobotDFPlayerMini/>

　DFRobotDFPlayerMiniデフォルトのスケッチサンプルからGetStartedを選ぶ。

![](/2022-12-22/4945208-03.png)

　スケッチの方にソフトシリアルのライブラリを使う指定があるので、ライブラリマネージャーから追加で入れる。

```cpp
#include "SoftwareSerial.h"
```

![](/2022-12-22/4945208-04.png)

![](/2022-12-22/4945208-05.png)

　スケッチの方に配線の指定があるので、それに従う。

```cpp
SoftwareSerial mySoftwareSerial(10, 11); // RX, TX
```

　IO11をRXに、IO10をTXに接続。抵抗のケースが見当たらないので、ノイズはある前提で抵抗は入れない。DFPlayerのシリアルは、ノイズが入りやすいという報告も読んだ。

![](/2022-12-22/4945208-06.png)

　スケッチの中身は、まず、初期化に3-5秒かかるという感じで待つ。初期化が終わったら、音量を10にセット。最大値は30のようだ。その後最初の楽曲を再生する。

```cpp
myDFPlayer.volume(10);  //Set volume value. From 0 to 30
myDFPlayer.play(1);  //Play the first mp3
```

　loopの中で、タイマーをセットして3秒たったら次を再生する。

```cpp
static unsigned long timer = millis();
if (millis() - timer > 3000) {
timer = millis();
myDFPlayer.next();  //Play next mp3 every 3 second.
}
```

　基本はこれだけ。

　スケッチを書き込む。動作開始すると、最初の再生は行われるのだけど、次のループは機能していないようだ。LEDが点灯したまま停止する。

　音量は10だと小さいので、最大の30にする。再生も音源の末尾に無音が入っているので、3秒も待ってられないので1秒にする。

　保存するとエラーになったので、スケッチ名を指定して保存しなおす。

![](/2022-12-22/4945208-07.png)

　なんか動くようになったのだけど、起動時にポップノイズが入るようになった。原因は不明。音量も上がっている。

　1秒未満のループ時間にしたら、再生終了は待っていないようなので、途中で切れて次の音源に進んでいる。4秒にしてやり直し。

　シリアルを見ると、なんかログが全部出ていない。コマンドは送れているようなので問題なさそう。やっぱ抵抗入れなかったからかな？

![](/2022-12-22/4945208-08.png)

　I/Oモードの回路もそのままにしてあるのだけど、ボタンは普通に機能しているようだ。

　なんか、標準ライブラリで動いてしまって拍子抜け。互換沼どこいった？

　しばらく、このネタで記事が書けると期待してたのだけど、ハズしてしまったじゃないの...

　互換ライブラリとしては、これがよく知られている感じ。

> Home · Makuna/DFMiniMp3 Wiki · GitHub<br>
> <https://github.com/Makuna/DFMiniMp3/wiki>

　ライブラリマネージャーにも表示される。

![](/2022-12-22/4945208-09.png)

　MH2024Kについてのディスカッションがある。

> MH2024K-16SS: errors, errors, errors · Issue #6 · ghmartin77/DFPlayerAnalyzer · GitHub<br>
> <https://github.com/ghmartin77/DFPlayerAnalyzer/issues/6>

　MH2024Kは、純正のライブラリでは動作しないのかと思ったけど、普通に動いているのはコントローラーのほうで互換性向上してるから？

　16Pでは苦労したけどダメだったって書いてある人がいる一方、16Pでも動いたという人もいる。同じ16P表記でも、使っているコントローラーやアンプにいろいろあって、動く動かないは、ライブラリ側での対応時期の問題か、コントローラー側の互換性対応が進んできた結果か。これも互換品の不思議。

　アンプの違いのほうは、音とかノイズ対策に特徴はあるようだけど、今のやつで音が出るという点では大差ないので気にしない。初期化時にポップノイズが「プツッ」と出てくる。これは再現性あり。I/Oモードでの動作時にはそういうことはなかったのだけど、なにかライブラリ側の問題だろうか？

　再生のループ時間を短くしたことで、短いデータでは途中で切れて終了前に次の再生コマンドが送られている。これがログが出てこない原因かな？と推測して、ループ間隔を７秒にしてみると、ログは安定して出るようになった。シリアル通信の問題ではなかった。

![](/2022-12-22/4945208-10.png)

　ポップノイズを低減できないかと、給電を3.3Vに変更してみたけどリセットに失敗して3回ほどプツプツ言ったり、ハムノイズがブーンと出たりしていたので、ちょっと不安定になった感じ。再生のほうは影響がない。5Vの運用がよさげ。このあたり、電気的な対応でなんとかできないかな。

　あとは、どのくらいのファイル数を扱えるのかが気になるところ。番号しゃべるだけの音声ファイルないかしらん？
