　昨日からなんかおかしい感じ。パームレストが暖かい。M1になってから、こういうことは稀だ。動画編集とか、オンラインミーティングとかしてないのに常時熱い。

　もっとも、Intel CPUの時のような耐え難い感じではない。でも、なんかおかしいのだろう。8/18

　ずっとスリープ運用でOSアップデートもやっていない。と、思ったらそうでもないか。

```text
% uptime
11:46  up 13 days, 16:04, 4 users, load averages: 1.38 2.57 4.02
```

　アクティビティモニタをみると、サービスが２つCPUを食っている。再起動したら直るのかもしれないけど、それもいろいろめんどくさい。

![](/2022-08-30/4305322-01.png)

　fseventsdは、ファイルシステムのイベントロギングプロセスなのだそう。/dev/fseventsから状態を読み取り、イベントをディスク上のログファイル(/.fseventsd)に書き込んでいる。メディアはつながっていないので、なんか暴走している感じかな。

　強制終了してみる。

![](/2022-08-30/4305322-02.png)

　launchdによって再起動してきた。

![](/2022-08-30/4305322-03.png)

　CPU利用率も18.3%まで下がっている。

![](/2022-08-30/4305322-04.png)

　これで過熱についてはおさまった感じ。だいぶヌルく感じるようになった。

　もう１つのCPU使用率上位プロセスである、com.apple.quicklook.ThumbnailsAgentは、Quick Lookキャッシュを生成しているもののようだ。

　Quick LookはOS X 10.5から採用されていて、PDFや動画ファイルなどを開かずに、内容を見たり直接編集したりすることができる機能。ThumbnailsAgentは、このために、バックグラウンドでプレビュー用のデータを生成している感じ。Quick Lookのお世話にはあまりなっていないので、そんなことにCPUを食って熱くなるのはごめんだな。

　プレビューするファイルの抽出パターンの追加は、/Library/QuickLook/* .qlgeneratorとして格納されているそうだ。ここでファイルタイプの制限をかけられないかと思ったのだけど、ディレクトリはあるけどファイルはなかった。デフォルトで有効なものはシステム側で確保されているのだろう。

　Finderの関連プロセスなので、Finderを終了するとこちらも再起動されるそうだ。

　直接制御するにはqlmanageコマンドが用意されている。プロセスの停止と再開はこのコマンドできそう。

```text
% qlmanage --help
Usage: qlmanage [OPTIONS] path...
	-h		Display this help
	-r		Force reloading Generators list
	-r cache	Reset thumbnail disk cache
	-m [name ...]	Display statistics about quicklookd. Stats names:
			* plugins	Show the generators list
			* server	Show quicklookd life information
			* memory	Show quicklookd memory consumption
			* burst		Show statistics about the last burst
			* threads	Show concurrent accesses stats
			* other		Show other information about quicklookd
	-p		Compute previews of the documents
	-t		Compute thumbnails of the documents
	-x		Use quicklookd (remote computation)
	-i		Compute thumbnail in icon mode
	-s size		Size for the thumbnail
	-f factor	Scale factor for the thumbnail
	-F factor	Scale factor for the thumbnail, draw downscaled and compare to 1x
	-z		Display generation performance info (don't display thumbnails)
	-o dir		Output result in dir (don't display thumbnails or previews)
	-c contentType	Force the content type used for the documents
	-g generator	Force the generator to use
```

　ヘルプを見るに、停止することはできないようだ。

　キャッシュの削除。でも、これやると、再度キャッシュ作る方向でCPU負荷になりそう。

`qlmanage -r cache`

　キャッシュの無効化のオプションもあるようだけど、ヘルプには出てこないな。隠しオプションなのかな。

`qlmanage -r disablecache`

　とりあえず、強制終了してみる。

![](/2022-08-30/4305322-05.png)

　launchd配下なのに、再起動してこないようだ。優先度は低いプロセスなのね。

　OSを再起動するか、FInderを再起動するまでは起きてこないかな。

　それはそれでよしとして、不便だったら考えよう。

　CPUの利用率はこの２つを停止してみることで、ガッツリ下がった。マシンそのものの過熱もなくなって冷たくなった。
