　Raspi Imagerを使って拡張メニューで設定を行えば、デフォルトユーザーの情報を書き込んで起動することができることがわかった。

　これまでのRaspiOS開発陣の実装パターンから、Imagerでは、おそらく/bootにあたるFAT領域に何か起動時に読み込むファイルを置いて、Linux側のスタートアップスクリプトでその値をセットしているのではないかと考えられる。

　拡張メニューでの設定は、これまでどこに書き込まれていたのだろう？

　前のImager v1.6.2で焼かれたSDカードのFAT領域を見てみる。

　boot用のバイナリやdtb/dtboファイルなどを除くと、テキストで書かれていて設定に関係しているのは３つ。前の２つは前からあるもの。

　"config.txt"は、ブートローダーが読み込む設定ファイル。

　"cmdline.txt"は、前からあるkernelに渡すパラメータが書かれているファイル。

　"firstrun.sh"は、前にはなかったので、これが怪しい。

![](/2022-04-28/3691701-01.png)

　firstrun.shの中を見てみる。拡張メニューで指定した内容を設定するシェルスクリプトで、ホスト名を設定、デフォルトユーザーをUIDで拾ってssh鍵を置く、sshdの設定でパスワード接続をオフにして、sshdを有効にして、自分自身を削除して、cmdline.txtからも削除している。

　一回こっきりで削除されるスクリプトなのだけど、FAT上に置かれているし、bootはほとんど改変されないパーティションなので、これは簡単にファイルの復活をさせて中を読み取れてしまうよ。とても危険だ。

```text
#!/bin/bash

set +e

CURRENT_HOSTNAME=`cat /etc/hostname | tr -d " \t\n\r"`
echo pi4-2 >/etc/hostname
sed -i "s/127.0.1.1.*$CURRENT_HOSTNAME/127.0.1.1\tpi4-2/g" /etc/hosts
FIRSTUSER=`getent passwd 1000 | cut -d: -f1`
FIRSTUSERHOME=`getent passwd 1000 | cut -d: -f6`
install -o "$FIRSTUSER" -m 700 -d "$FIRSTUSERHOME/.ssh"
install -o "$FIRSTUSER" -m 600 <(echo "ssh-rsa (略)") "$FIRSTUSERHOME/.ssh/authorized_keys"
echo 'PasswordAuthentication no' >>/etc/ssh/sshd_config
systemctl enable ssh
rm -f /boot/firstrun.sh
sed -i 's| systemd.run.*||g' /boot/cmdline.txt
exit 0
```

　firstrun.shは、kernelへの起動パラメーターとしてsystemdで起動するように書かれている。さらに、起動に成功したら、再起動するように指示されている。

```text
console=serial0,115200 console=tty1 root=PARTUUID=4a422963-02 rootfstype=ext4 fsck.repair=yes rootwait quiet init=/usr/lib/raspi-config/init_resize.sh splash plymouth.ignore-serial-consoles systemd.run=/boot/firstrun.sh systemd.run_success_action=reboot systemd.unit=kernel-command-line.target
```

　セキュリティの観点からは、拡張メニューを使った設定は使わないほうがいい。

　v1.7.2でもSDカードを作ってみる。ユーザー登録分のスクリプトが増えているだけで、あとは同じのようだ。

```text
#!/bin/bash

set +e

CURRENT_HOSTNAME=`cat /etc/hostname | tr -d " \t\n\r"`
echo pi4-4 >/etc/hostname
sed -i "s/127.0.1.1.*$CURRENT_HOSTNAME/127.0.1.1\tpi4-4/g" /etc/hosts
FIRSTUSER=`getent passwd 1000 | cut -d: -f1`
FIRSTUSERHOME=`getent passwd 1000 | cut -d: -f6`
install -o "$FIRSTUSER" -m 700 -d "$FIRSTUSERHOME/.ssh"
install -o "$FIRSTUSER" -m 600 <(printf "ssh-rsa (略)") "$FIRSTUSERHOME/.ssh/authorized_keys"
echo 'PasswordAuthentication no' >>/etc/ssh/sshd_config
if [ -f /usr/lib/userconf-pi/userconf ]; then
/usr/lib/userconf-pi/userconf 'pi' '$5$9WTBh5Nszc$4W2GktvgQhEeAB/bpHgZkd1SIghry96kBJAHi8errp7'
else
echo "$FIRSTUSER:"'$5$9WTBh5Nszc$4W2GktvgQhEeAB/bpHgZkd1SIghry96kBJAHi8errp7' | chpasswd -e
if [ "$FIRSTUSER" != "pi" ]; then
usermod -l "pi" "$FIRSTUSER"
usermod -m -d "/home/pi" "pi"
groupmod -n "pi" "$FIRSTUSER"
if grep -q "^autologin-user=" /etc/lightdm/lightdm.conf ; then
sed /etc/lightdm/lightdm.conf -i -e "s/^autologin-user=.*/autologin-user=pi/"
fi
if [ -f /etc/systemd/system/getty@tty1.service.d/autologin.conf ]; then
sed /etc/systemd/system/getty@tty1.service.d/autologin.conf -i -e "s/$FIRSTUSER/pi/"
fi
if [ -f /etc/sudoers.d/010_pi-nopasswd ]; then
sed -i "s/^$FIRSTUSER /pi /" /etc/sudoers.d/010_pi-nopasswd
fi
fi
fi
systemctl enable ssh
rm -f /boot/firstrun.sh
sed -i 's| systemd.run.*||g' /boot/cmdline.txt
exit 0
```

　うーん、拡張メニューでの設定はないわー。

　拡張メニューを使わなければ、firstrun.shが生成されないのを確認した。
