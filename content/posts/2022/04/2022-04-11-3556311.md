　どうやら、coreはバイナリというかライブラリでOSSではないが、APIサーバーはPythonで書かれたものがOSSになっているようだ。ライセンスはLGPL3と別途ご相談の有償っぽいデュアルライセンスになっている。

　coreはx64のようなのだけど、Raspi4でも動くようなことが書かれている内容も見かけるので、arm64のものも頒布されているのだろう。

　おや？ これによると、音声データのもとになるもの以外については、完全にOSSになっているようだ。エンジン以外のエディターとコアもOSSになっている。ちょっとびっくりした。コアはMITライセンス、エディタはLGPL3。

　ニュースメディアでは、こういう点についてはあまり触れられていない感じ。これから誰か解説を書いていくのだろうな。

　最新の状況はよくわからないけど、Qiitaなどを読むとOSSになっているものだけでは再現環境を作ることはできないようだ。環境構築を試すのも面倒なので、インストールしたアプリ版をAPIで使ってみる。

　ポート50021で、ローカルで動いているサーバーと通信できる。APIドキュメントも内蔵している。

<http://localhost:50021/docs>

![](/2022-04-11/3556311-04.png)

　動作的には、一度文字列を送ってJSONデータを得て、それを再加工したあとに渡して音声データにレンダリングする感じの使い方のようだ。アウトプットはwav形式。

　/audio_query

　音声合成用のクエリを作成する

　textとspeakerをパラメータに与えて、分かち書きデータを得る。

```text
% mkdir -p Documents/VOICEVOX_test
% cd Documents/VOICEVOX_test
```

　サンプル通りに叩いてJSONが出るか確認。

```text
% echo -n "おはこんばんちわ！" >text.txt
% curl -s -X POST "localhost:50021/audio_query?speaker=1" --get --data-urlencode text@text.txt
```

　JSONは出ている。APIで使うのは、アプリケーション版でも同じようだ。

　エンジンへのデータの引き渡しには、AquesTalk記法が使えるようだ。GUIほどは細かい設定はできないけど、アクセントや無音などの制御はできる。サンプルでは、「バ」にアクセントが設定されている。アクセントはワードに１つ。ワード区切りはスラッシュになる。

　変換前に一旦テキストファイルに吐き出す必要があるのは、なんかイヤだな。直接渡しはこれでいいのかな？

```text
% curl -s -X POST "localhost:50021/audio_query?speaker=1" --get --data-urlencode "text=あ"
{"accent_phrases":[{"moras":[{"text":"ア","consonant":null,"consonant_length":null,"vowel":"a","vowel_length":0.318695068359375,"pitch":5.7902655601501465}],"accent":1,"pause_mora":null,"is_interrogative":false}],"speedScale":1.0,"pitchScale":0.0,"intonationScale":1.0,"volumeScale":1.0,"prePhonemeLength":0.1,"postPhonemeLength":0.1,"outputSamplingRate":24000,"outputStereo":false,"kana":"ア'"}%
```

　うまくいった感じ。

　どっちかというと、パラメータ渡しはこっちのほうが好みだな。

```text
% curl -s -X POST "localhost:50021/audio_query" -d "speaker=1" --get --data-urlencode "text=あ"
```

　あとは、localhost:50021/synthesisに出来たJSONを食わせると、wavに変換してくれる。さらに出来たwavファイルをVLCでコマンドライン再生する。wavを一回ファイルに出さないといけないのはイマイチ。

　とりあえず、ざっくりとこんな感じのワンライナーで流してみる。「あ」の音が出た。

```text
% TEMP=`curl -s -X POST "localhost:50021/audio_query" -d "speaker=1" --get --data-urlencode "text=あ"`; curl -s -H "Content-Type: application/json" -X POST -d $TEMP "localhost:50021/synthesis?speaker=1" --output sound.wav; /Applications/VLC.app/Contents/MacOS/VLC -I dummy --no-loop ./sound.wav vlc://quit
VLC media player 3.0.16 Vetinari (revision 3.0.16-0-g5e70837d8d)
[000000015a9e1230] dummy interface: using the dummy interface module...
[000000015a8049e0] idummy demux: command `quit'
```

　パラメータを先頭に持ってくる。wavファイルを削除する。

```text
SP="1"; CONT="はろー"; TEMP=`curl -s -X POST "localhost:50021/audio_query" -d "speaker=$SP" --get --data-urlencode "text=$CONT"`; curl -s -H "Content-Type: application/json" -X POST -d $TEMP "localhost:50021/synthesis?speaker=1" --output sound.wav; /Applications/VLC.app/Contents/MacOS/VLC -I dummy --no-loop ./sound.wav vlc://quit; rm sound.wav
```

　キャラ指定やピッチなどの細かい制御はともかく、ワンライナーで声を再生することはできるようになった。

　さて、この音声を動画のキャラにリップシンクさせて、デモ動画を作ろうとすると、セリフ書く->VOICEVOXで音声データを作成->リップシンク型のキャラに食わせつつ、同時にアクションをつける->動画に保存、みたいなプロセスになるか。めんどくさいな...

　とりあえず、こんな感じのシャベリを作ってみる。

```text
SP="1"; CONT="おはようございます！きんねこの薄い本屋です。きょうは春めいたいいお天気でしたね。みなさんいかがお過ごしでしょうか？本日はボイスボックスについてお話したいと思います。"; TEMP=`curl -s -X POST "localhost:50021/audio_query" -d "speaker=$SP" --get --data-urlencode "text=$CONT"`; curl -s -H "Content-Type: application/json" -X POST -d $TEMP "localhost:50021/synthesis?speaker=1" --output sound.wav; /Applications/VLC.app/Contents/MacOS/VLC -I dummy --no-loop ./sound.wav vlc://quit; rm sound.wav
```

　デフォルトのパラメーターでは、「お天気」「でしたね」と「みなさん」の抑揚がおかしい感じ。やっぱ、ワンライナで出さないで、細かい調整が必要になりそうだ。
