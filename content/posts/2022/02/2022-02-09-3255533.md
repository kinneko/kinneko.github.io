　ファームウエアの更新は成功したのだけど、Y軸の逆転ができないのは変わりなし。

　しょうがないので、ファームウエアのソースコードいじって、空いているサーボドライバのポートに移動してみる。

　多くの3Dプリンタ用のボードには、サーボのドライバが５つ付いている。3DP-17では、サーボは５つあるのだけど、Z軸の２つは同じポートにパラレルに接続されているので、一番端のポートは空いている。調子の悪いY軸のドライバをやめて、接続先をここに移動してみようというわけだ。そのためには、ソースコードの変更が必要になる。

![](/2022-02-09/3255533-x4g1vqbi004yzu3nUlZzu2wd.png)

　とはいっても、ビルド用の設定ファイルを一部だけ書き換えれば対応可能ではないかと思う。

　まずは、ボードのシルク印刷を確認する。Y軸は「MOTO_Y」、空いているポートは「MOTO_E1」と書かれている。Eはエクストルーダーのことらしい。

　つまり、このボードは、デュアルエクストルーダーとして設計されたボードだということだ。3DP-17には、確かにそういうオプションがあったようだが、ほんとのデュアルヘッドというわけではなく、１つのノズルに２つのフィラメント共有できるようなものだったようだ。

![](/2022-02-09/3255533-dtnOAfQI4eWE0sgIrTetJUQ2.png)

![](/2022-02-09/3255533-ywqJCbuRpTKS7GuKUwyTQpAB.png)

　一般的には、Marlinのボードのピンマップ指定は「pins_YOUR_BOARD.h」というボード名入りのファイルになっているらしい。3DP-17のソースコードでは、ボード名のない「pins.h」になっていた。乱暴な実装ですね。

　pins.hファイルの中を見てみると、Y軸とMOTO_E1の設定は以下のようになっている。

```text
#define Y_STEP_PIN          2
#define Y_DIR_PIN           3
#define Y_ENABLE_PIN       19
#define Y_STOP_PIN         36

```

　ここでは、E1は書かれていない。使ってないからかな。数字の並び順からすると、E1はこんな感じだろうか。

```text
#define E1_STEP_PIN         8
#define E1_DIR_PIN          9

```

　これだと、なんか単純すぎるな。E1が定義されていないのも気になる。

　さらに下のほうを見ていくと、上書きで再定義されていた。E1の定義もちゃんとある。

```text
#define Y_STEP_PIN 39 // A6
#define Y_DIR_PIN 40 // A0
#define Y_ENABLE_PIN 38
#define Y_MIN_PIN 2
#define Y_MAX_PIN -1 //15

#define E1_STEP_PIN 36
#define E1_DIR_PIN 35
#define E1_ENABLE_PIN 37

```

　これを差し替えてやるとよさそう。Y_MIN_PINは、エンドストップのピンだろうから、変更しないでそのまま使う。

```text
% cp pins.h pins.h.org
% vi pins.h

% diff -Naur pins.h.org pins.h
--- pins.h.org	2022-01-10 17:29:55.000000000 +0900
+++ pins.h	2022-01-10 17:40:20.000000000 +0900
@@ -113,9 +113,9 @@
#define X_MIN_PIN          47
#define X_MAX_PIN          -1   //2 //Max endstops default to disabled "-1", set to commented value to enable.

-#define Y_STEP_PIN         14 // A6
-#define Y_DIR_PIN          15 // A0
-#define Y_ENABLE_PIN       39
+#define Y_STEP_PIN         37 // origin 14 // A6
+#define Y_DIR_PIN          40 // origin 15 // A0
+#define Y_ENABLE_PIN       36 // origin 39
#define Y_MIN_PIN          48
#define Y_MAX_PIN          -1   //15

@@ -129,9 +129,9 @@
#define E0_DIR_PIN          35 //35
#define E0_ENABLE_PIN       33 //33

-#define E1_STEP_PIN         37 //37
-#define E1_DIR_PIN          40 //40
-#define E1_ENABLE_PIN       36 //36
+#define E1_STEP_PIN         14 // origin 37 //37
+#define E1_DIR_PIN          15 // origin 40 //40
+#define E1_ENABLE_PIN       39 // origin 36 //36

#define Y2_STEP_PIN         37
#define Y2_DIR_PIN          40

```

　ビルドして書き込む。

![](/2022-02-09/3255533-gApXPq51A9vJ8jRgeQnsDeWX.png)

　ファームの書き込みはうまくいったので、Y軸の配線をE1に変更し、通電して動作確認する。

　だが、Y軸はまったく動かない。そんなに簡単にはいかなかったか...

　さわってみると、サーボに力がまったくかかっていないので、通電もできていないようだ。

![](/2022-02-09/3255533-1ifYLPAdM9cyc2X8sJejTHKL.png)

　ふとボードの写真を見ていると、何かが変な気がした。あれ？ Y軸のコネクタの配線の色並びがぜんぜん違うな...

![](/2022-02-09/3255533-VTGz1mfBX91bi3vK2GfBwN1o.png)

　確認してみると、X,YとZ,エクストルーダーの組み合わせで違っている。

　同じソケットで同じサーボがつながっているのに、配線の並びが違うのは何故なんだろうか？ なにか合理的な理由があるんだろうか？ 配線間違えると動かないようにしているとか？

　これを揃えないと、通電もできないどころかドライバが壊れそうね。すでに、もう壊れたかもしれない...

　E1のピンの並びは実際にはどうなっているのだろう？ ZやE0と同じなら、青赤緑黒なんだろうけど。今は緑黒青赤のYのケーブルをつなげている。それではまったく動かないので、並びを変えてみるしかなさそうだけど。

　とりあえず、エクストルーダーの配線を使ってチェックしてみるか。それにしても、線の並びを変えてあるのは、意図的なんだろうけど... なんでだろう？

　discordで聞いてみたら、Ender系のボードでは、エクストルーダーについてはサーボの回転方向が逆転になるのでピン配置を変えているという意見も聞いた。でも、普通はハーネス側かソフトウエアで変えるような... BOM管理的にもソフトでやったほうがよさげ。

　やれることは、３つありそう。

・サーボ側のピン並びも確認

・E1にE0エクストルーダー用のハーネスを付け替えて動作確認をする

・Yのコネクタのハンダがクラックとかしてないか調べてみる
