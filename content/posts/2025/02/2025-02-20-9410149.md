　LLMモジュールとM5Stick C Plus2との通信は、/dev/ttyS1で行われている。CPlus2には、スケッチが書き込まれている。ここまでは前にやったところ。

![](/2025-02/9410149-02.png)


　　LLM Moduleを普通に使う｜kinneko｜pixivFANBOX

　　https://kinneko.fanbox.cc/posts/9376067


　socatでシリアルポートを仮想化して、中継し、ミラーした結果を取ろうかと思ったけど、なかなかうまくいかない。

　基本的な考え方は、/dev/ttyS1を/dev/ttyS1_realにリネームし、socatコマンドを使って/dev/ttyS1という名前の仮想シリアルポートを作成し、それを/dev/ttyS1_realに接続するというもの。realのほうにデータがコピーされて流れてくるので、それを見るという感じ。

　でも、うまくいかないので放棄する。


 　llm_sysの設定で、使用するシリアルポートが指定できれば、もう少し楽なのだけど、残念ながら設定ファイルには、そのための情報がない。telnetのポート設定があるので、シリアルもあるかもしれないのだけど、ハードコードの可能性もないでもない。


　さて、あとは出力の解釈が面倒だけど、straceを使って、やりとりをモニタする方法がある。

　ログが短いのは、リセットでプロセスが再起動されてしまって、当初のプロセスが終わっているからか...


　リセットが起きているのは、Arduinoのスケッチでは、このあたりの処理の後になる。


```
    while (1) {
        if (module_llm.checkConnection()) {
            break;
        }
    }
```


　checkConnection()は、M5ModuleLLM.cppにあるけど、リセットはしてない感じ。


```
bool M5ModuleLLM::checkConnection()
{
    const bool result = (sys.ping() == MODULE_LLM_OK);
    llm_version       = (sys.version() == MODULE_LLM_OK);
    return result;
}
```


　応答は正常に返っているので、エラーでリセットが発動しているわけではなさそう。リセットどこでしよるとね？


　リセット後にstraceを再度プロセスIDを入れて動かすけれど、やっぱり欠ける部分がある。
