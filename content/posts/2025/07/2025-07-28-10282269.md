```text
LEDはWS2812Eを8x8=64個使っているので、電気食いそう... 熱くなりそう... サイズ面でATOMと同じデザインにしたいというのはわかるのだけど、ここまで密度をあげなくてもよかったような。4x4にしてコストダウンして複数使うみたいのとか、サイズのこだわりを捨てるとか。
LEDには仕切りがあって、漫然と並んでいるのとは違って隣への光漏れがないので、表示用としては鮮明に見える。
```

　連結形状からするとこのプラグでは一方向に長いしか連結できない。並べるときには普通のGroveケーブルで接続したらいいのかな。不細工だけどw 連結した時の消費電力も気になる。普通にマイコンユニットからの電源供給で足りるのだろうか。いくつなら繋げられるのかな？ 電源ラインを別に確保する専用のユニットが１ついるかも。

　なんか、何に貼るわけでもなさそうな長いラベルシールが付属しているのだけど、これはLEDの輝度と消費電力の目安が書かれているようだ。特段の理由がない限り、最低輝度で使うのがよさげ。

　Arduinoからの制御は、Adafruit_NeoPixelかFastLEDのリンクがあるだけで、サンプルコードなどはない。ATOM Liteにつないで使ってみる。

　Adafruit_NeoPixelだと、普通にマトリックスLEDを使うように指定したらいいみたい。でも、これだと、長く連結しない場合は自分でマトリックスを変換しないとダメそうね。

　どれか１つを赤色で点滅させるスケッチ。

```text
#include <Adafruit_NeoPixel.h>
#define LED_PIN 26     // Puzzle Unit制御用ピン（PORT.Aの信号線）
#define NUM_LEDS 64    // 8x8 マトリクス
Adafruit_NeoPixel pixels(NUM_LEDS, LED_PIN, NEO_GRB + NEO_KHZ800);
```

　void setup() {

```text
pixels.begin();
pixels.setBrightness(20);  // 輝度調整（最大255）
pixels.clear();
pixels.show();
}
```

　void loop() {

```text
// 1つだけ赤く光らせる（例：中央のLED）
int ledIndex = 27; // 中央付近（5行目・4列目あたり）
pixels.clear();
pixels.setPixelColor(ledIndex, pixels.Color(255, 0, 0)); // 赤
pixels.show();
delay(500);
// 消灯
pixels.clear();
pixels.show();
delay(500);
}
```
