仕様書をword形式で書けとうるさい。無理やりテキストで通して来たけど、外注に出す文書でフォーマットを統一する必要があったので、mdからの変換をやってみることにした。

　結論から書くと、あんまりうまくはいかなかったので、これ以下は読む必要はない。２回続くけどw

　変換は、pandocが一般的と聞いている。Haskell製の汎用ドキュメント変換ツール。

> Pandoc - About pandoc<br>
> <https://pandoc.org/>

　OPMLの変換もできるのか、OmniOutlinerからの変換も行けそうね。

　だいぶ古いけど、日本語ドキュメントもある。

> Pandoc ユーザーズガイド 日本語版 - Japanese Pandoc User's Association<br>
> <http://sky-y.github.io/site-pandoc-jp/users-guide/>

　変換用のmdファイルを用意する。pandocで変換できるmd形式にはいくつかあるようだ。

　markdown_strict 		ベーシックなMarkdown

　markdown 			pandoc拡張のMarkdown

　commonmark 		CommonMark Markdown

　gfm 				GitHub-Flavored Markdown

　markdown_mmd 		MultiMarkdown

　markdown_phpextra 	PHP Markdown Extra

　基本的なマークダウンでは、あんまり表現が多彩ではないので、pandoc拡張のMarkdownを使ってみることにする。

> Pandoc - Pandoc User’s Guide<br>
> <https://pandoc.org/MANUAL.html#pandocs-markdown>

　こんなmdファイルを用意してみた。

　------------------------------------------------------------------------------

　% タイトル

　% 著者1; 著者2

　% 日付

　# ヘッダ１

　本文ほにゃらら[^1]という脚注。

　[^1]ヘッダ前には空行は必須

　## ヘッダ1.1

　記号付きリスト

　* リスト１

　* リスト2

　インデントはスペース４つ

　さらにインデント

　### ヘッダ1.1.1

　順序付きリスト

　1. リスト１

　2. リスト2

　#### ヘッダ1.1.1.1

　テーブルの前には空行必須。

　+---------------+---------------+--------------------+

　| なんとか          | かんとか          | だよね          |

　+:=============:+==============:+:===================+

　| なんか          | おなかが        | - すいた           |

　+---------------+---------------+--------------------+

　| とても          | のどが         | - かわいた            |

　段落ほにゃらら

　段落ほにゃらら

　段落ほにゃらら

　####### ヘッダ1.1.1.1.1.1.1.1

　段落ほにゃらら

　######## ヘッダ1.1.1.1.1.1.1.1.1

　段落ほにゃらら

　変換する。一瞬で終わってしまった。

```
$ pandoc md_data.md -o word_format.docx
$ ls -lha word_format.docx
```

　-rw-r--r--  1 kinneko  staff    10K  4  1 14:00 word_format.docx

　エディタの設定で改行がCRだけになっている。改行設定をCR+LFにしないとダメかな。落とし穴っぽい。

　改行コードを変更したらうまくいったようだ。同じくSlackのプレビューで見てみる。

![](/2020-04-02/932644-pTYyV9Ix.png)

　うーん、そのまま使うことはできないな...

　指定の文書フォーマットを使いたい場合は、テンプレートを指定することができる。

　作った文書のテンプレートを、Wordでテンプレート(.dotx)として保存する。ドキュメント¥Officeのカスタムテンプレート以下に保管される。

　今回はめんどくさいので、MSの配布しているテンプレートの中から「ビジネス文書」をダウンロードして使ってみる。

> ビジネス文書<br>
> <https://templates.office.com/ja-jp/%e3%83%93%e3%82%b8%e3%83%8d%e3%82%b9%e6%96%87%e6%9b%b8-tm16392933>

![](/2020-04-02/932644-chXMV6Lt.png)

　tf16392933.dotxがダウンロードされた。先程のサンプルmdにテンプレートを指定して変換してみる。

```
$ pandoc md_data.md --reference-doc=tf16392933.dotx -o word_format.docx
```

　念の為、こんどはwordで開いてみた。

　それを、PDFにして画像化してみたが、罫線が再現されていないな。縦棒とか寄せがおかしいが、word上では罫線は表示されている。

　ダメな感じで使えない機能が多かったようだ。テーブルは崩壊。著者と日付は未定義のようだ。テンプレートで未定義のヘッダはそのまま表示されてしまうようだ。脚注とリストが展開されていない。

　十分とは言えないがないよりはマシ... なのかなぁ...

![](/2020-04-02/932644-3mK8mwHj.png)

![](/2020-04-02/932644-kpOO1w1Z.png)

　期待したのと違って、だいぶ残念な結果だった。テンプレートとのあいだで、だいぶマッチングをしっかり設計しないとうまくいかないようだ。

　pandocでmd/word変換、使う人があまりいないわけだw

　これなら、docxをunzipして、word/document.xmlを直接変換するパーサーを作ったほうがよさそうな気がしてきてしまう。
