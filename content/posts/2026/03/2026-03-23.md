　自前でビルドしてまでやる気はないのだけど、ボードの開発元の提供するArduinoIDE用のボード定義ファイルを読み込んでいるので、これをopenwchの公式JSONに差し替えてみることはできる。

　一応、UIAPの定義は削除する。ArduinoIDEの設定からJSONを削除して、ArduinoIDEを終了してボード定義を削除。

% rm -rf ~/Library/Arduino15/packages/UIAP

　openwchの公式はここ。

GitHub - openwch/arduino_core_ch32: Core library for CH32duino · GitHub

https://github.com/openwch/arduino_core_ch32

　指定すべき公式のJSONはこれ。

https://github.com/openwch/board_manager_files/raw/main/package_ch32v_index.json

　Githubにあるように、wchを検索したけど、出てこないな...

　ArduinoIDEで見ると、WCH公式版にはopenocdは入っているがminichlinkは入っていないのね。

% find ~/Library/Arduino15/packages/WCH/tools/ | grep minichlink

% file ~/Library/Arduino15/packages/WCH/tools/openocd/1.0.0/bin/openocd

/Users/kinneko/Library/Arduino15/packages/WCH/tools/openocd/1.0.0/bin/openocd: Mach-O 64-bit executable x86_64

　この構成では、書き込みにWCH-LinkEが必要になる感じ。

　Aliexpressでは普通に売っているけど、USB Type-Cではないし、なんか５ピンの端子がいるっぽい。300円基板のUSBと反対側にある４つのパッドがそれっぽい。標準品ではない、専用のジグがいりそうな気配。んで、こっちはたぶん、シリアル接続。

![](/2026-03-23/19EniECRqJPhld0sKYKBFrpb.png)

　WCH-LinkEとの組み合わせでも、macOSで動く実績はあるっぽい。

GitHub - patryk4815/ch32v-nix: GDB debugger openocd WCH-LinkE ch32v CH32V003 blackmagic macos apple · GitHub

https://github.com/patryk4815/ch32v-nix

　一応、ArduinoIDEでの書き込みツールの表示も確認してみる。こんな感じ。

　minichlinkだけをビルドする。

% cd ch32fun/minichlink

% make

gcc -o minichlink minichlink.c pgm-wch-linke.c pgm-wch-isp.c pgm-esp32s2-ch32xx.c nhc-link042.c ardulink.c serial_dev.c pgm-b003fun.c minichgdb.c chips.c ch5xx.c -lpthread -framework CoreFoundation -framework IOKit -framework Security -L/opt/homebrew/Cellar/libusb/1.0.29/lib -lusb-1.0  -O0 -Wall -Wno-asm-operand-widths -Wno-deprecated-declarations -Wno-deprecated-non-prototype -D__MACOSX__ -DMINICHLINK -DCH32V003 -I. -I/opt/homebrew/Cellar/libusb/1.0.29/include/libusb-1.0

gcc -o minichlink.so minichlink.c pgm-wch-linke.c pgm-wch-isp.c pgm-esp32s2-ch32xx.c nhc-link042.c ardulink.c serial_dev.c pgm-b003fun.c minichgdb.c chips.c ch5xx.c -lpthread -framework CoreFoundation -framework IOKit -framework Security -L/opt/homebrew/Cellar/libusb/1.0.29/lib -lusb-1.0  -O0 -Wall -Wno-asm-operand-widths -Wno-deprecated-declarations -Wno-deprecated-non-prototype -D__MACOSX__ -DMINICHLINK -DCH32V003 -I. -I/opt/homebrew/Cellar/libusb/1.0.29/include/libusb-1.0  -shared -fPIC

　できた。ちゃんとarm64バイナリになっている。

% file ./minichlink

./minichlink: Mach-O 64-bit executable arm64

　ArduinoIDEを終了して、openwchを削除。

% rm -rf ~/Library/Arduino15/packages/WCH/

　前にやったように、ArduinoIDEを起動して、UIAPのJSONを追記して、ボードを追加。platform.txtを修正。

% mv ~/Library/Arduino15/packages/UIAP/tools/minichlink-2982dfd/1.0.0/minichlink ~/Library/Arduino15/packages/UIAP/tools/minichlink-2982dfd/1.0.0/minichlink.x86

　ビルドしたminichlinkをコピーして直接差し替える。

% cp minichlink ~/Library/Arduino15/packages/UIAP/tools/minichlink-2982dfd/1.0.0/

　ArduinoIDEを再起動して、ビルドと書き込み。

　またエラー。

　スケッチの書き込み中にエラーが発生しました

　VID:0x1209, PID:0xb003

Error: Could not initialize any supported programmers

　minichlinkが相手のUSBデバイスを「対応プログラマ」として掴めていない。

　この300円ボードではopenwch標準と違って、USB PIDが変更されているということかな？

　単体実行でも同じエラーがおきるね。オプションでUSB IDを渡す方法もない感じ。

% ./minichlink

　VID:0x1209, PID:0xb003

Error: Could not initialize any supported programmers

　minichlink.c内の0x1209b003を0x1209b803に変えればよさそう。

% grep 0x1209b003 ./*

./minichlink.c:			dev = TryInit_B003Fun(SimpleReadNumberInt(init_hints->serial_port, 0x1209b003));

./minichlink.c:		else if ((dev = TryInit_B003Fun(SimpleReadNumberInt(init_hints->serial_port, 0x1209b003))))

./minichlink.c:	fprintf( stderr, " -c [serial port for Ardulink, try /dev/ttyACM0 or COM11 etc] or [VID+PID of USB for b003boot, try 0x1209b003]\n" );

Binary file ./minichlink.exe matches

Binary file ./minichlink.so matches

　書き換えて、お掃除、ビルド。

% make clean

rm -rf minichlink minichlink.so minichlink.exe

% make

　実行してみる。

　リセットすると、USB側のLEDが8回点滅して消えた。真ん中のLEDはずっと点滅している。これでいいのかな？

　USB側の小さいLEDは、USB通信のモニタをしているものらしい。たしかに、プログラムの書き込み時にはずっと点灯している。
