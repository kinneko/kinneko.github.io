　さて、素直に動くとは思えず、めんどくさいことが予想されるのはESP32環境だ。

![](/2021-04-23/2079055-X3QXQ5JTDGP2rraDFkfG1T5Y.jpeg)

　まず、シリアルドライバから。

　ESP32の板を差し込むと、普通に認識していますね... こちらも拍子抜けか？

![](/2021-04-23/2079055-3kkVZMfGXMWWmacPgvQx0agh.png)

```
kinneko@kinnekonoMacBook-Pro ~ % ls -l /dev/cu.usbserial-0001
crw-rw-rw-  1 root  wheel    9,   7  4  1 16:08 /dev/cu.usbserial-0001
```

![](/2021-04-23/2079055-bPnNA5Or8SYbm446jleWB3B5.png)

　一応、本家をたどって状況を確認する。

> CP210x USB to UART Bridge VCP Drivers - Silicon Labs<br>
> <https://www.silabs.com/developers/usb-to-uart-bridge-vcp-drivers>

![](/2021-04-23/2079055-DkFDLxWWpxNNWZTbcr632cag.png)

　「CP210x VCP Mac OSX Driver　v6.0　12/22/2020」と書かれているリンクからダウンロードする。zipファイルが展開されて、２つのファイルが出てきた。

・macOS_VCP_Driver_Release_Notes.txt

・SiLabsUSBDriverDisk.dmg

　リリースノートを開いてみる。

![](/2021-04-23/2079055-6QYbo1im6niFziSYTM0MIhSp.png)

　6.0からDriverKit extensionに対応しているようだ。

　Web上の表記とは違って、最新版は"6.0.1 - March 26, 2021"になっている。こういう細かいところがちゃんとしてないのって、気になるよなぁ...

　インストール済みのdextファイルを確認してみる。シリアルは代表的なFTDI, Profilic, SiliconLabs, WCHには対応できているようだ。"com.apple.DriverKit-AppleUSB"というファイル名からするに、これってmacOS純正サポートしたってことなんだろうか。サードパーティから提供されるシリアルドライバは腐っていることが多いし、バージョンアップの結果も微妙なので、歓迎すべきことかもしれない。

```
kinneko@kinnekonoMacBook-Pro ~ % ls /System/Library/DriverExtensions/
com.apple.AppleUserHIDDrivers.dext
com.apple.DriverKit-AppleEthernetE1000.dext
com.apple.DriverKit-AppleUSBCHCOM.dext
com.apple.DriverKit-AppleUSBFTDI.dext
com.apple.DriverKit-AppleUSBPLCOM.dext
com.apple.DriverKit-AppleUSBSLCOM.dext
com.apple.DriverKit-AppleUSBSerial.dext
com.apple.DriverKit.AppleUserECM.dext
com.apple.DriverKit.AppleUserECMData.dext
```

　com.apple.DriverKit.AppleUserEthernetASIX.dext

　"/System/Library/DriverExtensions/com.apple.DriverKit-AppleUSBSLCOM.dext/Info.plist"の中をみると、バージョン情報っぽいものは以下の内容だ。

```
<key>CFBundleInfoDictionaryVersion</key>
<string>6.0</string>
```

　リリースノートを読んでも、違いはCP2102を使っているESP32モジュールには関係なさそうだ。最新の6.0.1ではないが、上書きインストールはせずに、このまま進めることにする。そのうち、再起動の必要なOSのアップデートで一緒に最新版が降ってくるのを期待しよう。

```
Version 6.0.1
On macOS Big Sur:
Fix issue with CP2105 that it cannot transfer data if Software flow control is enabled.
Fix installation error under some conditions.
On macOS Catalina or older:
Add support for Line Break to the driver.
Fix RTS doesn't go high if host PC buffer is full.
Improve throughput.
```

　あとは、通常通りESP32の開発環境をArduino IDEに導入する。

　Arduino IDEの環境設定を開いて、ボードマネージャのダウンロード先を追記する。

![](/2021-04-23/2079055-ZDN0E5a7ATj3MJJykBqzahd0.png)

![](/2021-04-23/2079055-RscOnx8wrgUxoq5HFa53RKRp.png)

![](/2021-04-23/2079055-EXaBIChaJm5lOgcsJ7LgFuVM.png)

<https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json>

　Arduino IDEを一度終了して、再起動する。ツール->ボード->ボードマネージャーを起動する。

![](/2021-04-23/2079055-TlpNLg1xvgsKZZnDeBvGAJy5.png)

　ESP32で検索する。

![](/2021-04-23/2079055-q6gnJMgpsl4z0UNBEeloKOqN.png)

　ボードが出てくるので選択して、インストールする。

![](/2021-04-23/2079055-pWAyiDNF606U8gIus32jmjoU.png)

![](/2021-04-23/2079055-4GbeGd4vg80QnRB4lidTzs0c.png)

　インストールが終わると、INSTALLEDという青緑色の文字が表示される。終わったら閉じるボタンを押す。

![](/2021-04-23/2079055-opvBlcHwg1Op2leuYeDYMfRp.png)

　ツール->ボードを選ぶと"ESP32 Arduino"が追加されていれば成功。

![](/2021-04-23/2079055-wMBgXidtngKh9H2PXCcVv0Kk.png)

　以前と違って、ボードのプリセットがだいぶ増えている。今回のターゲットにしている"Node32s"を選ぶ。

![](/2021-04-23/2079055-4ddCLr48XaH0uF5Wp6LnA2hQ.png)

　ツール配下がNode32sに切り替わっているので、シリアルポートで、先ほど確認したデバイスを選択する。

![](/2021-04-23/2079055-u1mai9pT5mfDUTF39EK4FhDB.png)

　シンプルなLEDテストのスケッチを書いて、ターゲットに書き込んでみる。

```
const int ledPin = 2;
void setup() {
pinMode (ledPin, OUTPUT);
}
void loop() {
digitalWrite (ledPin, HIGH);
delay(1000);
digitalWrite (ledPin, LOW);
delay(1000);
}
```

　おっと、エラーになった。

![](/2021-04-23/2079055-H126nJFadpivGIh2kWe3XCaH.png)

```
Arduino：1.8.13 (Mac OS X), ボード："Node32s, Default, 80MHz, 921600, None"

最大1310720バイトのフラッシュメモリのうち、スケッチが198438バイト（15%）を使っています。
最大327680バイトのRAMのうち、グローバル変数が13248バイト（4%）を使っていて、ローカル変数で314432バイト使うことができます。
esptool.py v3.0-dev
Serial port /dev/cu.usbserial-0001
Connecting........_____....._____....._____....._____....._____....._____....._____

A fatal error occurred: Failed to connect to ESP32: Timed out waiting for packet header
A fatal error occurred: Failed to connect to ESP32: Timed out waiting for packet header
```

　あぁ、このモジュールは、コンデンサの配線がダメで、セルフリセットできないやつか...

　ボタンでリセットすると、無事に書き込み終了。

![](/2021-04-23/2079055-CbGFE202cfHYxTK3OzaDFvSY.png)

　書き込み後、マニュアルでボタンリセットすると、1秒間隔の点滅を確認できた。

![](/2021-04-23/2079055-5DCwx3ogLisbGOGo9EBrUAFe.jpeg)

　あれ？トラブルとか全然ないじゃん... つまらん。

　事前調査では、setuptoolで使うpyserialがないとか、setuptoolのファイル名にpyがないとダメとか、置くPathがダメなところにあるのでコピーしないといけないとかというトラブルが予想されたので楽しみにしていたのに、ライブラリ側ですっかり解消されてしまっている。ありがたいことですw
